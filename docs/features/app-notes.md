# App notes

Spec: `docs/superpowers/specs/2026-11-05-app-notes-design.md`. Each app has a notes page of standing facts (how it's built and released, which worker or machine to use, gotchas), for Adam to look things up and for every chat on the app to start with. It is OtherBench's own CLAUDE.md plus `#` "remember", kept out of git.

- **Where it lives.** Migration `041-app-notes`: `app_notes` (one row per app, synced, `app_id` a real foreign key with cascade) and `app_notes_version` (the last 50 saves, this machine only). `mirrored_at` is this machine's last good write to Collectives and never syncs (`LOCAL_COLUMNS`). The pure parts are in `core/src/domain/app-notes.ts`: the starting headings (Build, Release, VM / workers, Gotchas), placing, moving, editing and removing a line, `factFromMessage` (a one-line message starting with a single `#`), the `<save-note section="…">…</save-note>` offer tag, the prompts and the Collectives text.
- **Chats.** `TurnPromptBuilder.withAppNotes` adds `appNotesPrompt` after project memory for any chat with an app, for both engines. It is read fresh every turn (only the user changes the notes, so nothing churns), and it tells the model how to offer a fact with the tag.
- **Adding a fact.** In an app chat the composer sends a `# fact` line to `POST /api/apps/:id/notes/facts` instead of the model, then shows a card in the thread (`FactCards`, this window only) with Edit, Move and Undo. A model's offer tag in a reply renders as a Save card (`TextWithNoteOffers` in `AppNoteCards.tsx`), which posts to the same route with the model's heading as a hint; a card whose line is already in the notes shows "Saved". The server (`server/src/app-notes/service.ts`) asks the memory model (the Memory model setting, then the app's default, then the app default profile) for the heading and the line the fact replaces, as JSON, through `askMemoryModel`; a replaced line is only taken if it is really in the notes. Without a model or on a failure, the fact goes under the given heading or **Other**.
- **Collectives.** One way: after every save the notes are written to `<the app's wiki page>/Notes` in its collective (`writeWikiPage`, which makes missing pages), headed by a line saying the page is a read-only copy. An app with no wiki page isn't copied. A failed write is kept for the Notes tab and retried on start-up and every 10 minutes; Nextcloud off or not set up just skips it. "Copied" means `mirrored_at` equals `updated_at`, and each save's time is made later than the last, so no save can be mistaken for an earlier one.
- **Web.** The **Notes** tab in the Code panel (after Links; it stays with Nextcloud off) reuses `MemoryNote` for Edit and History, and says where the Collectives copy stands. The app home has a **Notes** card with "Open all notes". `state/appNotes.ts` caches each app's notes and polls every 30 s while the tab or card is open.
- **Security posture.** User actions on `/api/apps` only, never the peer listener, never a model tool: a model can only offer a fact, and nothing is saved until Adam presses Save. A synced notes row is refused unless its app is here and its body is a string within 12,000 characters, since it reaches every app chat's prompt. Notes text is the user's own, but it is sent to whichever model the chat uses and to Nextcloud.
- **Known gaps.** Editing on Collectives is overwritten by the next save. "No" on a model's offer lasts only until the thread is drawn again. The fact cards are not kept across a reload. With two machines both set up for Nextcloud, a synced save is copied by each of them (the same text, so harmless).
- **Tests.** `core/test/app-notes.test.ts`, the store contract cases, `store-sqlite/test/sync.test.ts`, `server/test/app-notes/service.test.ts` (filing, replacing, the mirror and its retry, the routes), and `web` beside the code (`NotesTab`, `AppNoteCards`, `Composer`, `CodePanel`).
