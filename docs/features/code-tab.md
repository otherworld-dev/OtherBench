# Code tab

Spec: `docs/superpowers/specs/2026-10-20-code-tab-design.md`. The sidebar has a **Chat | Code** switch. Code mode lists **apps** instead of projects. An app is one repo, a folder plus an optional GitHub `owner/name`, with any number of chats under it. Code mode has a git bar above the chat, and a right panel with Issues, Files and Chat tabs. The Chat tab is the old Inspector. The git panel and issue actions are for doing things by hand. Claude still does most git work in the chat with its own tools.

- **Where it lives.** Migration `029-apps` adds the `app` table and `chat.app_id`. Both sync like projects: `app` has an `hlc` and sync triggers and sits after `project` in `SYNC_TABLES`. `app_id` has no foreign key because of sync ordering, and a link to a missing project is cleared. A chat has an app or a project, never both. Deleting an app moves its chats back to Chat mode through the crud layer, so the change syncs, and nothing is deleted. For an app chat, `projectChain` (`core/src/domain/turn-prompt.ts`) is the app's linked project, plus that project's parent. So the linked project's instructions, memory note and extra folders reach app chats as they reach its own chats (the viewer opens files in those folders too, and the project index marks the linked project as the chat's own), but app chats never feed that project's memory summariser.
- **Server.** `packages/server/src/code/`:
  - `process.ts` is the one process runner. It spawns an argv array with `shell: false`, resolves the executable with `resolveExecutable`, and passes `withoutServerSecrets(process.env)`. It caps stdout at 5 MB and stderr at 1 MB, and it has timeouts.
  - `git.ts` runs the git service. Committing some files goes through a scratch index built from HEAD (`GIT_INDEX_FILE`, a temp file this module makes and removes): a rename's old side and deleted files are taken out of it, the rest is added from disk, it is committed, and the real index is then reset to the new HEAD for just those paths, so other staged changes stay staged. `git commit --only` isn't used, because it refuses a case-only rename on Windows and macOS ("will not add file alias") and re-adds a file untracked with `git rm --cached`. An error's message is git's `error:`/`fatal:` line, not the `warning:` lines (CRLF on Windows) printed before it.
  - `github.ts` runs the issues service through the machine's own `gh` and its login. OtherBench stores no GitHub token. `gh` is resolved once and the path reused, as `git` is, since on Windows the lookup is a synchronous `where`.
  - `routes/apps.ts` holds the routes: `/api/apps` CRUD and `detect-repo`; `/:id/git/{status,diff,commit,pull,push,branches,checkout,branch}`; `/:id/issues[/:n[/comment|close|reopen]]`; `/:id/files` and `/:id/text`. Errors are `{ error, code, stderr? }` with a `GitErrorCode`/`GhErrorCode` from `core/src/types/code.ts`. They answer 4xx, never 500.
  - An app's folder resolves with `resolveWorkspace`. Where it doesn't resolve, every git, issue and file route answers `not-on-this-machine`.
- **Web.** `packages/web/src/code/`:
  - `CodePanel` shows the tabs. Its app follows the focused pane.
  - `IssuesTab` lists issues and shows one issue's detail.
  - `FilesTab` is the shared `DirTree` over `/apps/:id/files`. With an app chat focused, a file opens in that chat's viewer. Without one, it shows read-only.
  - `AppHome` is the centre view for an `app:` tab: details, New chat, the app's chats and its issues.
  - `GitBar` and `GitPanel` show the branch, ahead/behind, the changed files with their diffs, commit, pull, push, and switching or creating a branch.
  - `startChatFromIssue` pre-fills the composer with the issue and never sends it, unless an issue start command is set in Settings, Features (`issueStartCommand`, e.g. `/start {issue}`; empty by default): then that is sent at once, with `{issue}` as `#<number>`. The Overview's Chat on an issue notification goes through it too.
  - `useCodeRefresh` refreshes on window focus and after `turn-finished` in any of the app's chats. ↻ refreshes by hand. There is no file watcher.
  - `views/AppView.tsx` is the app form. It fills the name from the folder and the GitHub repo from the remotes.
  - Elsewhere:
    - `lib/changedFiles.ts` builds the "changed in this chat" list from the chat's own successful edit and write calls, across the whole message tree.
    - `lib/editDiff.ts` shows an edit as a diff in every chat, in both modes.
    - "Move to app…" and "Move out of app" are in the chat menu.
  - **Mode.** Each mode keeps its own tabs and panes. They are saved under `otherbench.panes` and `otherbench.panes.code`, and the mode under `otherbench.mode`, per browser and not synced. Opening an app chat from anywhere switches to Code mode. Search lists the showing mode's chats in its groups, and the other mode's matches in a trailing "In Code mode" / "In Chat mode" section, so a chat can be found from either mode. After a sync the app list is reloaded with the chats and projects.
- **Security posture.**
  - **User-only.** The git and issue routes are user actions on server routes. They are never model tools, so they don't pass the `PermissionBroker` and add no route around it.
  - **Not on the peer listener.** The routes are mounted only on the authed `/api` (`app.ts`), never on the peer listener (`forwardedApi`). A paired machine can't commit, push or comment through this one. `test/routes/apps.test.ts` ("the peer listener") checks that every `/apps` path is a 404 there.
  - **Fixed argv.** Nothing from a request is spliced into a command line.
    - Every git call gets one fixed prefix: `--no-pager --literal-pathspecs -c core.quotepath=false -c core.fsmonitor=false -c color.ui=false`.
    - Diffs add `--no-ext-diff --no-textconv`.
    - Commit messages are separate argv values.
    - Branch names must pass `git check-ref-format --branch`, and a name starting with `-` is refused.
    - A NUL in a branch or a message is a 400.
    - An issue number must be a positive integer. The repo always goes in as `--repo owner/name`, after `isGithubRepo` checks it. A comment body goes in on stdin (`--body-file -`).
  - **Environment.** git's environment drops the variables that would point it at another repository or config (`GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_COMMON_DIR`, every `GIT_CONFIG*`). Prompts and the pager are off (`GIT_TERMINAL_PROMPT=0`, `GIT_PAGER=cat`, `GH_PROMPT_DISABLED=1`).
  - **Contained paths.** Every path from the UI, whether a file to stage or diff or a folder to list or read, goes through `containPath` against the app's resolved root. It is then handed to git after `--` as a literal pathspec. A path that escapes is `bad-path`.
  - **Credentials.** None are stored. git and gh use the machine's own. URLs with credentials in them are redacted from the stderr the UI shows.
- **Known gaps.**
  - **No forwarding to the other machine.** Git always runs on the machine serving the UI. For a chat that runs elsewhere, the bar says "Runs on <machine>: git shows this machine's copy", and commit, pull, push and the branch controls are off. Issues still work, because they come from GitHub.
  - **No pull requests, and no creating issues.** There is also no merge, rebase, stash or conflict resolution in the git panel. Claude does those in the chat, or Adam uses his own tools.
  - **Shell changes aren't counted.** Files changed by shell commands don't appear in "changed in this chat". The list counts only edit and write tool calls (spec Goal 6, accepted). The git panel's changed files are the real `git status`.
  - **Repo config can still run programs, and not only when Adam clicks something.** Hooks, clean/smudge filters, `gpg.program`, `core.sshCommand`, `credential.helper` and `core.askPass` all stay live, as they do in a terminal. Only fsmonitor, external diff and textconv are turned off. That covers every git call the panel makes, including the automatic status and diff refreshes (on window focus, when a turn in one of the app's chats finishes, and on ↻): a clean filter runs whenever status or diff has to look at a changed file's content, so it can run with no click at all. Hooks can too: `post-index-change` runs whenever git rewrites the index, and both the status and the diff refresh do that after a file changes (checked live), on top of the hooks that commit, switch, pull and push fire. Also, a model with a broad write grant can write to `.git/`, for example to plant a filter or a `post-index-change` hook that runs on the next refresh, or a commit hook that runs when Adam clicks Commit. That is the same exposure as running git in a terminal today. Closing `.git/**` writes in the broker is a separate piece of work.
  - **A chat can be left under "Unknown app" by a sync race.** If one machine deletes an app while the other moves a chat into it, the chat's `app_id` can arrive after the app's deletion has cleared the others, so it names an app that no longer exists. Code mode shows it under "Unknown app" rather than losing it, and "Move out of app" in its menu sends it back to Chat mode (accepted, final review M7).
  - **The app folder must be the repo's top level.** A subfolder of a repo reports "Not a git repository (the app folder must be the top folder of its repository)". This keeps pathspecs and `add -A` scoped to the app. Issues and Files still work for such an app.
  - **GitHub only.** Issues come from GitHub through `gh`. Gitea, where `origin` lives, isn't supported.
  - **Cross-site GETs.** A cross-site no-cors GET can make `detect-repo`, `/files` or `/text` stat a UNC path, which could leak NTLM credentials on Windows. This is the same class as `/api/fs/dirs` today, and it's a follow-up card candidate.
  - **The Code panel shares the Inspector's collapse preference** (`otherbench.inspectorCollapsed`).
- **Tests.**
  - Server: `server/test/code/` (`git-parse`, `git` against temp repos, `github` with an injected runner), `server/test/routes/apps.test.ts` and `apps-files-escape.test.ts`.
  - Core and the store: `core/test/apps.test.ts`, the store contract suite, and the app cases in `store-sqlite/test/sync.test.ts` and `migrations.test.ts`.
  - Web: unit tests beside each file in `web/src/code/`, plus `lib/changedFiles.test.ts` and `lib/editDiff.test.ts`.
  - e2e: `packages/web/e2e/code-tab.spec.ts` makes a temp git repo with one commit and creates the app through the API, because the folder picker can't be driven. It then goes through the UI: Code mode, the app home, a new chat answered by the mock, the branch in the git bar, Files, and the chat missing from Chat mode. It also checks that Code mode's tabs come back after a mode switch and a reload. Issues aren't covered, because CI has no `gh`. The spec skips itself when `git` isn't installed.
- **Open apps.** Spec: `docs/superpowers/specs/2026-11-04-open-apps-design.md`. The Code sidebar lists only the apps that are open (`app.open`, migration `040-app-open`, set with `PATCH /api/apps/:id`). At its top is an **All apps** entry that opens the All apps page (tab id `apps:all`): sections per folder then Unfiled, cards, search, a Grid/List switch, and a click anywhere on a card opens its app (for the keyboard, the app's name is the card's button, with its ⋯, **Actions for <name>**, beside it rather than inside). Hovering or focusing an open app's heading shows a × (**Close <name>**), and on a touch screen (a coarse pointer) the × always shows in place of the count; closing toasts "Closed <name>. It's still in All apps." with Undo, and Undo puts focus on the app's heading. A toast waits while it is hovered or has focus, then gets what was left (at least 3 s, `TOAST_RESUME_MS`). An app's home has **Close app** / **Keep in sidebar** and a breadcrumb `All apps / <folder> / <app>`. A closed app still shows in the sidebar while a card of it waits on you or a chat is running, with a line saying why. The sidebar keeps the All apps order, and an app's heading can be dragged, or moved with Move up / Move down in its menu, but only past the shown apps of its own folder (or the top level), since the sidebar draws no folders. Closed apps between them keep their place (`shownAppSiblings`, `sidebarAppBeforeId`). Both are off while searching, and filing an app into a folder stays on the All apps page. e2e: `packages/web/e2e/open-apps.spec.ts`.
- **App folders.** Spec: `docs/superpowers/specs/2026-10-25-app-folders-design.md`, moved to the All apps page by the Open apps work above. Apps are grouped into one level of folders, and the folders are managed on the All apps page (`AllAppsPage`, `AllAppsSection`, `AllAppsCard`, state in `useAppOrganiser`), not in the sidebar, which lists only open apps. **+ New folder** opens the name for editing (it clears a search first, and a double-click makes one folder). A section per folder, then Unfiled, each foldable; Unfiled is left out when empty, except while a filed app is being dragged, so there is always somewhere to drag one out of its folder. An app is filed by dragging its card onto a section or another card, or by **Move to folder…** in the card's menu (hidden when there are no folders; "No folder" takes it out). Cards and folders reorder by drag or Move up/down in their menus. A folder's menu has Rename, Move up, Move down and Delete…; deleting a folder moves its apps to Unfiled and deletes none (the confirm says so). Dragging is off while searching. **Move to app…** on a chat lists the apps in folder order (`codeSidebarAppOrder`).
  - **Where it lives.** Migration `032-app-folders` (the schema is now 32) adds the `app_folder` table and `app.folder_id`. `app_folder` has an `hlc` and sync triggers and syncs like `app`. `folder_id` is not a foreign key, for the reason `app_id` isn't: sync applies rows in no fixed order, so an app can arrive before its folder. The folder repo's `delete` clears `folder_id` itself, through the app repo so that change syncs, and every reader treats a folder that is missing as none, so the app shows at the top level. Routes: `/api/app-folders` CRUD, and `folderId` on an app's `PATCH`.
  - **Fold state** is per machine: the `otherbench.collapsedGroups` list in localStorage, with `folder:<id>` keys (`folderKey`). It isn't synced. Filing an app into a folded folder opens it, so the app stays in view.
  - **Web.** The page builds its sections from the apps and folders in the store; the drop, order and filing patches are `fileAppPatches`, `moveAppPatches`, `moveFolderPatches` and `placeFolderPatches` in `panes/sidebar/model.ts`, and `useAppOrganiser` runs them.
  - **Known gaps.** A failed move reloads only the apps. Only a folder's name can be renamed in place; there is no nesting of folders.
  - **Tests.** Unit tests beside the code in each package, and `packages/web/e2e/app-folders.spec.ts`: creates two apps through the API, then on the All apps page makes a folder with + New folder, renames it from its menu, drags an app's card onto it with real browser drag-and-drop (Playwright's `dragTo` fires the HTML5 events in Chromium, so it needs no synthetic events), folds it, reloads and finds it folded with its count, files the second app with Move to folder…, reorders a folder with Move up, then deletes the folder and finds both apps Unfiled. jsdom fakes `DataTransfer`, so this is the only test of a real drag.
