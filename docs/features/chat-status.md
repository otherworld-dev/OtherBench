# Chat status: done, or what's left

Spec: `docs/superpowers/specs/2026-11-15-chat-done-status-design.md`. At the end of a turn the agent says whether everything agreed in the chat is finished, or what is still left. The chat's row then says **Done** or **2 left** where it would say **Your turn**, so finished chats can be checked and archived without asking the chat whether anything is left.

- **The tool.** `set_chat_status { done, left? }` (`packages/core/src/domain/chat-status-tool.ts`: name, description, parameters, `parseChatStatus`, `runStatusCommand`, `agentStatusOf`). `done: true` takes no items (a `null` list counts as none); `done: false` takes 1 to 20, each `{ text, who }` with the text trimmed and cut at 200 characters. `who` says who the item waits on: `you` (the user must do, check, decide or answer something), `me` (the agent does it once told to carry on) or `parked` (agreed to leave for later). Replies saved before `who` existed hold plain strings; those, and an item with no `who`, parse as untagged items (`{ text }`). The description tells the model to call it as the last step of any turn where work was done or agreed, to cover the whole conversation (parked items included), not the current task's steps, to say in its reply what the user needs to do for every `you` item (the card shows only the short lines), and to call it again every turn. Added 2026-11-18 because a bare "Left:" list didn't say whether the user had to do anything.
- **Stores nothing.** Like the checklist, the tool only checks its arguments and answers ("Status set: done." / "Status set: 2 left."). The status is read back from the reply's parts: its last top-level `set_chat_status` call whose result came back without an error (neither `isError`, which Claude Code sets, nor a `{ error: true }` result, which is how the API engines store a refusal) and whose arguments parse (`agentStatusOf`). So there is no migration or column. A new reply has no status until the agent sets it again, a retry clears it with the reply's parts, each compare variant and branch has its own, and a paired machine gets it with the message row.
- **Who may call it.** Source `'thread'`, so the broker allows it without a card. API sub-agents never get thread tools and are refused one; a Claude Code helper (`shownSubagent`) is refused this tool too (`SUBAGENT_STATUS_REFUSAL`, `permissions/sources.ts`), and a helper's calls sit inside its `subagent` part, so they couldn't count anyway. Models that can't use tools aren't offered it.
- **API engines.** `statusTool()` in `packages/tools/src/thread-tools.ts`, one of `threadTools()`, so every profile gets it.
- **Claude Code.** One of OtherBench's own tools on the per-process server, like `propose_plan`: `otherBenchStatusTool` (`otherbench-server.ts`), `own.status` and the `status` binding (`reply-binding.ts`), the `'status'` own-tool name (`approval.ts`, `process-launch.ts`), renamed back to `set_chat_status` in the reply's parts. It is on when the engine is built with `chatStatusTool: true`, which the server's container sets.
- **The chat list.** `heads()` (both store adapters) adds `ChatHead.agentStatus` when the tip is a complete assistant reply with a status. Only each chat's tip is read past its id, and of its parts the SQL returns just its own top-level `set_chat_status` entries (`json_each`), so the list parses next to nothing. On 571 open chats it took about 61 ms whether or not chats carry a status, where reading the whole parts took 111 ms once every tip had one.
- **The word.** `chatStatus` (`web/src/state/chatStatus.ts`) returns `'done'` or `'left'` in place of `'your-turn'`; a failed reply still says Failed, and a card still comes first. Both need the user (they get the tick and count in `needsYouChats`) but aren't cards and don't keep an app live. Ticking or replying clears them, as for Your turn. Unlike Your turn, they ignore the 7-day window (`CHAT_NEED_WINDOW_MS`): a chat marked Done and never archived is the one to find. `needWindowStart` (`core/src/domain/overview.ts`) is that rule, used by the sidebar's `chatStatus` and the Overview's "Tick off older than…" (`tickOlder`); the Overview's own list keeps the plain window. `StatusWord` shows **Done** (green, `--success`); **N for you** (amber, N counting only the `you` items) when anything waits on the user; a muted **N left** when every item is `me` or `parked`; or an amber **N left** when untagged items (older replies) are in it. The hover lists every item under its group (`groupLeft`). It shows wherever a chat's word shows (sidebar row, tabs, app and project pages); the All apps card counts them as "Work left".
- **In the thread.** `ChatStatusCard` under the reply: a green "Done: nothing left in this chat" line, or the items grouped as "Waiting on you" (amber), "Next from me", "Parked" (both muted) and, for untagged items, "Left" (amber), with empty groups left out, on a reply that finished or is still being written (not one that failed or was stopped, whose row says so). A call that took isn't drawn as a tool; one that didn't (refused, or bad arguments: `failedStatusCalls`) is, so a row that didn't change has a reason in the thread.
- **Mock.** `#status done` and `#status left a|you:b|me:c|parked:d` call the real tool (`packages/web/e2e/chat-status.spec.ts`); an item without a `you:`/`me:`/`parked:` prefix goes as a plain string, the older shape.
- **Tests.** `core/test/chat-status-tool.test.ts`, the store contract's "messages: heads", `tools/test/thread-tools.test.ts`, `engine-aisdk/test/mock-provider.test.ts`, `engine-claude-code/test/otherbench-server.test.ts` and `engine.test.ts`, `web/src/state/chatStatus.test.ts`, `StatusWord.test.tsx`, `ChatStatusCard.test.tsx`, `Message.test.tsx` and the e2e above.
- **Known limits.** It is only as good as the agent's judgement: nothing checks that a chat marked Done really is, or that a `you` item is explained in the reply. A chat from before this change has no status until its next reply sets one. A paired machine still on an older build reads a reply with `{ text, who }` items as having no status, so its row says Your turn until it updates.
