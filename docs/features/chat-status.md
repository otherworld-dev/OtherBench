# Chat status: done, or what's left

Spec: `docs/superpowers/specs/2026-11-15-chat-done-status-design.md`. At the end of a turn the agent says whether everything agreed in the chat is finished, or what is still left. The chat's row then says **Done** or **2 left** where it would say **Your turn**, so finished chats can be checked and archived without asking the chat whether anything is left.

- **The tool.** `set_chat_status { done, left? }` (`packages/core/src/domain/chat-status-tool.ts`: name, description, parameters, `parseChatStatus`, `runStatusCommand`, `agentStatusOf`). `done: true` takes no items; `done: false` takes 1 to 20, each trimmed and cut at 200 characters. The description tells the model to call it as the last step of any turn where work was done or agreed, to cover the whole conversation (parked items included), not the current task's steps, and to call it again every turn.
- **Stores nothing.** Like the checklist, the tool only checks its arguments and answers ("Status set: done." / "Status set: 2 left."). The status is read back from the reply's parts: its last top-level `set_chat_status` call whose result came back without an error (neither `isError`, which Claude Code sets, nor a `{ error: true }` result, which is how the API engines store a refusal) and whose arguments parse (`agentStatusOf`). So there is no migration or column. A new reply has no status until the agent sets it again, a retry clears it with the reply's parts, each compare variant and branch has its own, and a paired machine gets it with the message row.
- **Who may call it.** Source `'thread'`, so the broker allows it without a card. API sub-agents never get thread tools and are refused one; a Claude Code helper (`shownSubagent`) is refused this tool too (`SUBAGENT_STATUS_REFUSAL`, `permissions/sources.ts`), and a helper's calls sit inside its `subagent` part, so they couldn't count anyway. Models that can't use tools aren't offered it.
- **API engines.** `statusTool()` in `packages/tools/src/thread-tools.ts`, one of `threadTools()`, so every profile gets it.
- **Claude Code.** One of OtherBench's own tools on the per-process server, like `propose_plan`: `otherBenchStatusTool` (`otherbench-server.ts`), `own.status` and the `status` binding (`reply-binding.ts`), the `'status'` own-tool name (`approval.ts`, `process-launch.ts`), renamed back to `set_chat_status` in the reply's parts. It is on when the engine is built with `chatStatusTool: true`, which the server's container sets.
- **The chat list.** `heads()` (both store adapters) adds `ChatHead.agentStatus` when the tip is a complete assistant reply with a status. The SQL only brings a reply's parts when they mention the tool name.
- **The word.** `chatStatus` (`web/src/state/chatStatus.ts`) returns `'done'` or `'left'` in place of `'your-turn'`; a failed reply still says Failed, and a card still comes first. Both need the user (they get the tick and count in `needsYouChats`) but aren't cards and don't keep an app live. Ticking or replying clears them, as for Your turn. Unlike Your turn, they ignore the 7-day window (`CHAT_NEED_WINDOW_MS`): a chat marked Done and never archived is the one to find. `needWindowStart` (`core/src/domain/overview.ts`) is that rule, used by the sidebar's `chatStatus` and the Overview's "Tick off older than…" (`tickOlder`); the Overview's own list keeps the plain window. `StatusWord` shows **Done** (green, `--success`) or **N left** (amber) with the items on hover, wherever a chat's word shows (sidebar row, tabs, app and project pages); the All apps card counts them as "Work left".
- **In the thread.** `ChatStatusCard` under the reply: a green "Done: nothing left in this chat" line, or "Left:" and the items, on a reply that finished or is still being written (not one that failed or was stopped, whose row says so). The tool call itself isn't drawn as a tool.
- **Mock.** `#status done` and `#status left a|b` call the real tool (`packages/web/e2e/chat-status.spec.ts`).
- **Tests.** `core/test/chat-status-tool.test.ts`, the store contract's "messages: heads", `tools/test/thread-tools.test.ts`, `engine-aisdk/test/mock-provider.test.ts`, `engine-claude-code/test/otherbench-server.test.ts` and `engine.test.ts`, `web/src/state/chatStatus.test.ts`, `StatusWord.test.tsx`, `Message.test.tsx` and the e2e above.
- **Known limits.** It is only as good as the agent's judgement: nothing checks that a chat marked Done really is. A chat from before this change has no status until its next reply sets one.
