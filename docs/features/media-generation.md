# Media generation

Spec: `docs/superpowers/specs/2026-10-22-media-generation-design.md`. A chat model can make a picture or a short video through two tools, `generate_image` and `generate_video`, backed by a **generation connection** set up in Settings → Connections. Each profile says which connection and model or workflow it uses for images and for video (Settings → Profiles → Generation). Generation is off on every profile until it is set up, and OtherBench never probes for a ComfyUI unless you click Find ComfyUI.

- **Connection kinds.** `comfyui` (images and video; placeholder `http://127.0.0.1:8188`), `a1111` (A1111, Forge and SD.Next, images only; `http://127.0.0.1:7860`) and `openai_images` (`/v1/images/generations`, images only; `http://127.0.0.1:8080/v1`). They are never routed a chat turn, listed as a chat model or accepted as a profile's chat connection (`isGenerationKind`; the engine router and registry throw, `discover-models` answers 400, and the chat pickers leave them out). Secrets are in the `SecretStore` under `conn:<id>`, as for chat connections. **Test** on one calls `MediaBackend.test` (ComfyUI `/system_stats`, A1111 `/sdapi/v1/sd-models`, OpenAI `/models`). `GET /api/connections/:id/media-models` gives `{ models, checkpoints, checkpointsError? }` for the pickers. A loopback base URL pins the connection to this machine (`defaultAvailability`). A generation connection's base URL can't hold a `user:pass@` (400 on create and `PATCH`, telling an A1111 user to put `user:pass` in the API key field, which `mediaFetch` sends as Basic auth), and no error message ever names one (`withoutUserinfo`). A `PATCH` can't move a connection between the chat and generation kinds (400); within either side the kind can still change.
- **Profile.** `ToolPolicy.media` is `{ image?, video?, confirmPrompts? }`, each choice `{ connectionId, model, checkpoint? }`. `model` is a workflow id for ComfyUI, the `sd-models` title for A1111 and the model id for `openai_images`. `checkpoint` is ComfyUI only (refused on other kinds; 1 to 512 characters): the model file for the workflow's `checkpoint` binding. When the chosen workflow has one, Generation shows a **Model file** picker listing the files ComfyUI says it has; its default, "Workflow's own (<file>)", leaves `checkpoint` unset. The file run is the profile's choice, else the one saved with the workflow, else the graph's own (`fillWorkflow`), so the SDXL workflow works with a checkpoint not named `sd_xl_base_1.0.safetensors`. A profile with no image choice isn't offered `generate_image`, and the same for video. Video needs a `comfyui` connection. Sub-agents never get the tools.
- **Permissions.** `ToolSource` has `'media'`, risk `execute`, and it goes through `PermissionBroker` via `gate()` in `packages/tools/src/provider.ts` like every tool. Under `ask_on_mutate` it is allowed with no approval card (`grantedBy: 'policy'`), unattended runs too. Under `always_ask` it is grant- or card-gated, so an unattended run is refused without a grant. `confirmPrompts` defaults to true: the call then pauses on a **generation ask** (`AskInput` kind `generation`, `GenerationCard` in the thread) showing the prompt, negative prompt and settings, with **Generate**, **Edit** (the prompt becomes editable text) and **Cancel**. Whatever is generated with is what is sent and what the model is told was sent. With it on, an unattended run is refused rather than run unseen. With it off, generation starts straight away and the reply still shows the prompt.
- **Only what is applied is shown.** `MediaHost.backendFor` says what the backend takes of a request (`applies: { negativePrompt, seed, size, frames }`) and its own default negative prompt: A1111 takes everything and has no default; `openai_images` takes the size only; a ComfyUI workflow takes a setting only when it is bound (`workflowApplies`; size needs both width and height), and its default negative is the bound input's text in the graph. Where a negative prompt is taken, the ask is prefilled with the model's, else the workflow's own, so the default is seen and can be edited; what is sent is the reply's, and an emptied one is sent as `''`, which `fillWorkflow` writes over the workflow's own. Where it isn't taken, the ask has none and nothing is sent or reported. The ask's settings line and the result text list only applied fields: one a ComfyUI workflow doesn't bind reads "workflow default"; one `openai_images` doesn't have (seed) is left out. The audit row for the call records the prompt and negative prompt that were sent (`mediaAuditArgs`), not the model's.
- **Backends** (`packages/tools/src/media/`). `http.ts` (`mediaFetch`) keeps credentials on the connection's own origin, refuses every redirect (including a server's own http to https one, so the URL has to be the final one), caps and clips error text, and never echoes a bad key or header. `comfyui.ts` fills a workflow's bindings, `POST /prompt`, follows progress on the `/ws` websocket (default global `WebSocket`; no `ws` dependency) and falls back to polling `/history/{id}` every second, then downloads from `/view`. `a1111.ts` calls `/sdapi/v1/txt2img` and polls `/sdapi/v1/progress`. `openai-images.ts` calls `/images/generations` for `b64_json` (a returned URL is followed only on the connection's own origin). For a video, ComfyUI outputs under a `videos` or `gifs` key or named `.mp4`/`.webm` are taken before other files (at most 4 are downloaded). A1111 sends `override_settings_restore_afterwards: false`, so a checkpoint switch isn't undone after every image. `tool.ts` is the tool: arguments, the ask, progress, and the result (text with the prompt and, where applied, the negative prompt, seed, size and length, and the workflow or model, plus the media, so "darker" and "same again" work).
- **Stop.** The turn's abort cancels the job on the generator. ComfyUI always gets `POST /queue {delete:[id]}`, and `POST /interrupt {prompt_id}` only once the job is known to be running: an `execution_start`, `executing` or progress step for it was seen, or else `GET /queue` (asked after the delete) shows it in `queue_running`. A job that has finished is never interrupted, even when Stop comes while its file downloads, because an older ComfyUI's `/interrupt` stops whatever is running. A1111 gets `POST /sdapi/v1/interrupt`. Progress (queued, generating, saving, step N of M) is a stream event, replayed to a reconnecting client, and shown in the reply.
- **Workflows.** Two ship with the app (`packages/tools/src/media/workflows/`, ids `builtin:sdxl-txt2img` and `builtin:wan22-5b-t2v`). Imported ones are the synced `media_workflow` table (migration `031-media-workflows`): `POST /api/media/workflows/detect` reads a ComfyUI "Export (API)" JSON and guesses the prompt, negative prompt, seed, size and (video) length nodes; `POST`, `PATCH` and `DELETE /api/media/workflows` save the choice, which Settings → Workflows lets the user correct without editing JSON. An imported workflow has **Edit**, which opens the same form on its name, media, a binding per role and its model file, and saves through `PATCH /api/media/workflows/:id` (`checkpoint: null` goes back to the graph's own); the graph itself isn't changed. A binding to a linked input or to an input of the wrong type is refused. Where a workflow names a model file, the picker offers the files the ComfyUI says it has.
- **Model files the bundled workflows need** (from ComfyUI's own templates; the user installs them):
  - **SDXL** (image): `models/checkpoints/sd_xl_base_1.0.safetensors`. Base only, no refiner.
  - **Wan 2.2 5B** (video, text to video, 1280x704, 24 fps, mp4 h264 through the core `SaveVideo` node): `models/diffusion_models/wan2.2_ti2v_5B_fp16.safetensors`, `models/text_encoders/umt5_xxl_fp8_e4m3fn_scaled.safetensors` and `models/vae/wan2.2_vae.safetensors`.
- **Media in the reply.** Generated images and videos ride on the tool result as `{ type: 'image' | 'video', data, mimeType }`, are saved by `keepToolImages` / `saveToolImage` as attachments bound to the reply (so they survive reloads, sync and blob GC), and are shown by `GeneratedMedia` (image: inline, click for full size, download; video: a player with controls, download). Sync fetches a reply's videos up to 64 MB. A failed `generate_*` call shows its message plainly outside the tool fold, not only in the model's words. Caps: an image over `MAX_TOOL_IMAGE_BYTES` (5 MB) is refused with a note naming its size, never re-encoded; a video over `MAX_TOOL_VIDEO_BYTES` (64 MB) is refused; at most `MAX_TOOL_VIDEOS_PER_MESSAGE` (4) per reply.
- **The video exception to the inline-safe rule.** Until now attachment and tool content was served only as inert raster images. Generated video is a deliberate, narrow extension, and the checks are:
  - Only `video/mp4` and `video/webm`. The type is **sniffed from the bytes** (`sniffToolVideoMime`: an `ftyp` box at offset 4 for mp4, the EBML magic with a `webm` DocType in the first 64 bytes for webm), never taken from the generator's response, a stored row or a tool's label. Anything else is refused and not stored.
  - It is served only by the chat-scoped route `GET /api/chats/:chatId/messages/:messageId/tool-images/:attachmentId`, which answers one 404 for anything that isn't a video or image bound to that chat and to that message, and for a message that isn't an assistant reply. `toolVideoBound` holds the row to an allowlisted type and the 64 MB cap. The generic `GET /attachments/:id/content` and its `INLINE_SAFE_MIME_TYPES` are unchanged and still serve no video inline.
  - `Content-Type` is the sniffed literal, with `X-Content-Type-Options: nosniff` and `Content-Security-Policy: default-src 'none'; sandbox`. `Accept-Ranges: bytes` and a single `Range` are honoured so the player can seek (a malformed or multiple range gets the whole file, one past the end a 416).
  - SVG and HTML never render inline, for images or video.
- **Claude Code profiles.** They get `generate_image` and `generate_video` through the relay (`relayOtherBenchTools`), on the same `otherbench_<hex>` server, when the profile has the choice set, exactly as an API profile does. The relayed call carries Claude Code's tool-use id (`_meta["claudecode/toolUseId"]`) and the request's abort signal, so a generation card matches its call and Stop cancels the job on the generator. Claude gets images; a video is withheld from the model and replaced by the video-for-user note (`VIDEO_FOR_USER_NOTE`, core), while the reply still shows the player. Claude Code's own sub-agents (Task/Agent) and OtherBench helpers can't generate. A Claude Code helper's call is known by the PreToolUse hook's `agent_id` (canUseTool's `agentID`), so it doesn't depend on the helper's message having been read; a generation that carries neither waits up to 500 ms (`OWNER_WAIT_MS`) for the process's background tasks to say whether a helper made it, which also catches an earlier reply's helper still working in the background. Generated images also end up in Claude Code's own session files, as browser screenshots do.
- **Server timeout and auto-background.** The OtherBench server entry sets `timeout` to six hours (`OTHERBENCH_TOOL_TIMEOUT_MS`), so a long video isn't cut off at the default or at the user's `MCP_TOOL_TIMEOUT`, and the spawn env forces `CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS=0`, so Claude Code doesn't move a slow generation to the background and lose its result.
- **One card per generation.** Under `always_ask` with "Show me the prompt" (`confirmPrompts`) on and someone there, the broker allows the call before the tool's generation ask, rather than raising an approval card as well: that ask is the confirmation. The allow is only for an attended reply; an unattended `always_ask` run is still refused unless a grant covers it. Sub-agents and Claude Code helpers are refused whatever the mode. Both engines. With it off, `always_ask` still asks the ordinary way (a card, or a grant).

- **Checked against a real ComfyUI (2026-10-24).** ComfyUI Desktop 0.8.2 on port 8000 (Desktop's default, not 8188), RTX 3090 24 GB.
  - Both bundled graphs were accepted with no `node_errors` and ran: SDXL at 1024x1024 in 13.2 s, Wan 2.2 5B at 640x640 and 25 frames in 30.4 s. So the node input names (`CLIPLoader.device`, `SaveVideo` `format`/`codec`, `CreateVideo.fps`, `Wan22ImageToVideoLatent`) are right. SDXL is still base-only.
  - `SaveVideo` lists its file under `images` (subfolder `video`) with an extra `animated: [true]`, not under `videos`. `outputFiles` handles that: it skips the boolean and picks the file by its `.mp4` name. The file is H.264 in an mp4 box and sniffs as `video/mp4`.
  - Stop on a running Wan job interrupted it (`execution_interrupted`, no outputs) and left the queue empty, so `/interrupt { prompt_id }` works on 0.8.2.
- **Known gaps** (from the reviews, not fixed):
  - A job that vanishes from ComfyUI's queue is waited on until Stop. This matters for an unattended `ask_on_mutate` run with confirmation off.
  - A transient `/history` error or the 30 s submit timeout fails the call but leaves the job running on the GPU.
  - Stop on a job whose start the client hasn't seen relies on `GET /queue`; if that read fails, the job comes off the queue but a running one isn't interrupted.
  - The backend is resolved before the ask, so a connection or key edited while the card is up is used as it was.
  - The ask's settings line names the workflow but not the model file it will load.
  - The lightbox moves focus in and back but doesn't trap it. A progress line is hidden while any ask or approval card of the same tool is pending (matched by tool name, not call). The video route reads the whole blob for each range request.
  - A1111 and OpenAI images are only tested against fakes.

- **ComfyUI that fits an existing setup** (spec `docs/superpowers/specs/2026-10-25-comfyui-fit-design.md`; `packages/server/src/comfy-library.ts`, `packages/core/src/domain/media-workflows.ts`, `packages/tools/src/media/tool.ts`). Listing ComfyUI's history and templates is GET only; nothing in ComfyUI is ever changed.
  - **Find ComfyUI.** A button on a ComfyUI connection (`POST /api/connections/find-comfyui`) asks `GET /system_stats` on `127.0.0.1:8188` and `127.0.0.1:8000` (2 s each, on the server, only when clicked) and fills in the first that answers like ComfyUI. Nothing probes in the background.
  - **Recently run.** Lists the workflows in ComfyUI's `/history` that have `extra_data.extra_pnginfo.workflow`, so only runs started from ComfyUI's own page (OtherBench's and other API clients' jobs are left out; OtherBench now submits with a `client_id` starting `otherbench-`). Runs are grouped per workflow (`workflowShapeKey`, so runs that differ only by seed, prompt or model file collapse into the newest), newest first, with what was found (prompt, seed, size, length, negative, model file). **Add** opens the review form, then Save. The list reloads when its tab opens, when the window regains focus and on Refresh.
  - **Templates.** ComfyUI's own `/templates/index.json`, text-only ones (no `io.inputs`) for local models: names starting `api_` and `openSource: false` are paid cloud templates and are left out. The type comes from `io.outputs[].mediaType`, because a template's own `mediaType` is its thumbnail's (image even for LTX-2.3 video). Open in ComfyUI uses `?template=<name>`, which ComfyUI 0.8.2's front end supports (`useTemplateUrlLoader`) for names matching `/^[a-zA-Z0-9_.-]+$/`; other names show "Open Templates in ComfyUI and choose ...". A template can't be added from here: run it once in ComfyUI, then add it from Recently run. A ComfyUI without the index says so ("needs a newer ComfyUI").
  - **Size and length follow the workflow.** `generate_image` and `generate_video` offer `aspect` and `seconds` only when the workflow has them, and nothing outside its limits reaches ComfyUI (`workflowLimits`, `MediaHost.limitsFor`). Shapes are square 1, portrait 2/3, landscape 3/2, wide 16/9, rounded to a multiple of 16 for images and 32 for video; the frame rate is the workflow's own (`fps` / `frame_rate`), else 24. Wan 2.2 5B: 1280x704 or 704x1280 at most, up to 5 s (121 frames at 24 fps). A workflow with no size gets no `aspect` and the request carries no width and height (`MediaRequest.width/height` are optional).
  - **Detection through primitives.** `detectBindings` follows a prompt, seed, size or checkpoint that comes from a linked primitive node (such as `PrimitiveStringMultiline` into `CLIPTextEncode`), and `fillWorkflow` writes the value into the primitive.
  - **Profile warnings.** Settings → Profiles → Generation says when the chat model can't use tools, only for an `ollama` connection whose model has `supportsTools === false` (only Ollama reports real capabilities; for other kinds the default `false` doesn't mean it can't), and when the chat model and the generator share this machine's graphics card.
  - **Ollama unload.** For a profile whose chat connection is `ollama` on this machine and whose generation connection is also on this machine, the "Unload the chat model before generating" checkbox (`unloadChatModel`, on by default) sends `POST /api/generate {model, keep_alive: 0}` at Ollama's native root, after the ask is answered and before the job is submitted. A failure is swallowed: it never fails the generation.
  - **Checked by hand (2026-10-25).** The real template index has 76 local text-only templates (15 video). The `openSource: false` templates not named `api_` all use paid cloud nodes. Not yet checked end to end on Adam's machine, see the list below.
